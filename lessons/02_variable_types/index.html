Variable Types

A gradual path from simple inference to annotations, mut, shadowing, constants, and the advanced idea that Rust knows every type at compile time.

Open Quiz View Example Back to Course Hub

1. Simple inference

let age = 30;
let price = 19.99;
let active = true;
let letter = 'R';

Rust can usually infer obvious types. You do not need to annotate every variable.

2. Explicit types

let users: u32 = 120;
let temperature: i32 = -5;
let ratio: f32 = 0.75;

Annotations communicate intent and solve ambiguous cases.

3. parse() needs a target

let guess: u32 = "42"
    .parse()
    .expect("Not a number");

Without : u32, Rust may not know which numeric type you want.

4. mut keeps the same type

let mut count: i32 = 10;
count = 11;      // OK
count = "ten";   // Error

mut means changeable value, not changeable type.

5. Shadowing can change type

let spaces = "   ";
let spaces = spaces.len();

The second let creates a new variable. The name is reused, but the type can change.

6. Constants are typed forever

const MAX_USERS: u32 = 1_000;

Constants require an explicit type and use SCREAMING_SNAKE_CASE.

From Simple to Advanced

LevelPatternExampleIdea
1Inferencelet x = 10;Rust chooses the obvious type.
2Annotationlet x: i64 = 10;You choose the type.
3Mutablelet mut x = 10;Same type, value can change.
4Shadowinglet x = "10"; let x = 10;New binding, new type possible.
5Constantconst LIMIT: u32 = 100;Typed value that never changes.

Recap

  • Every Rust value has a type known at compile time.
  • Rust infers simple types, but annotations are useful and sometimes required.
  • mut changes values, not types.
  • Shadowing creates a new binding, so the type can change.
  • Constants always require explicit types.
