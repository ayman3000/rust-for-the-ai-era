Functions for AI Utilities

Learn functions without borrowing yet: simple inputs, clear outputs, and tiny AI utility helpers. Borrowing comes later when we need to pass real prompt text.

Teaching Boundary

This lesson avoids string references and borrowing. First we learn the shape of functions. Later, borrowing answers: “How do we pass real prompt text without copying or moving it?”

1. A function names a useful step

fn print_line(width: usize) {
    println!("{}", "=".repeat(width));
}

Simple input: a number. Simple action: print a separator line.

2. Parameters need types

fn estimate_tokens(character_count: usize) -> usize {
    character_count / 4
}

Rust wants every parameter type to be clear. Here, the input is just a number.

3. Return values use ->

fn prompt_fits_context(estimated_tokens: usize, limit: usize) -> bool {
    estimated_tokens <= limit
}

This function returns true or false. No borrowing needed.

4. Semicolons matter

fn bad() -> usize {
    10;
}

The semicolon turns 10 into a statement. The function no longer returns the number.

5. Return owned text

fn build_default_instruction() -> String {
    String::from("Answer clearly, simply, and with one practical example.")
}

This gives us a useful AI instruction without passing text into the function yet.

6. Intentional compiler lesson

error[E0308]: mismatched types --> missing_return_value.rs:11:47 | 11 | fn estimate_tokens(character_count: usize) -> usize { | --------------- ^^^^^ expected `usize`, found `()` 12 | character_count / 4; | - help: remove this semicolon

Rust tells you exactly what happened: the semicolon changed the return expression into no value.

Recap

  • Functions start with fn.
  • Parameters need explicit types.
  • Return types are written with ->.
  • The last expression without a semicolon is returned.
  • This lesson avoids borrowing so the function concept stays clean.
