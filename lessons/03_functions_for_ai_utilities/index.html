Rust for the AI Era · Lesson 03

Functions for AI Utilities

Learn functions by building tiny helpers we will reuse later: clean a prompt, estimate its size, and build a clear AI instruction. Simple concept, practical use, gradual explanation.

Open Quiz View Example Back to Course Hub

1. A function names a useful step

fn print_section(title: &str) {
    println!("\n{title}");
    println!("{}", "=".repeat(title.len()));
}

We use this helper to make terminal output easier to read while learning.

2. Parameters need types

fn clean_prompt(prompt: &str) -> String {
    prompt.trim().to_string()
}

Rust wants every parameter type to be clear. Here, the function receives text and returns a cleaned String.

3. Return values use ->

fn estimate_tokens(text: &str) -> usize {
    text.len() / 4
}

No semicolon on the last line means Rust returns that expression.

4. Semicolons matter

fn bad() -> usize {
    10;
}

The semicolon turns 10 into a statement. The function no longer returns the number.

5. Build a reusable AI instruction

fn build_instruction(task: &str, input: &str) -> String {
    format!("Task: {task}\n\nInput:\n{input}\n\nAnswer clearly and simply.")
}

This is the first small step toward prompt templates, Ollama calls, summarizers, and agents.

6. Intentional compiler lesson

error[E0308]: mismatched types --> missing_return_value.rs:11:35 | 11 | fn estimate_tokens(text: &str) -> usize { | --------------- ^^^^^ expected `usize`, found `()` 12 | text.len() / 4; | - help: remove this semicolon

Rust tells you exactly what happened: the semicolon changed the return expression into no value.

Recap

  • Functions start with fn.
  • Parameters need explicit types.
  • Return types are written with ->.
  • The last expression without a semicolon is returned.
  • Small functions make AI tools easier to build, test, and explain.
